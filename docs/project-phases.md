# فازبندی پروژهٔ همراه مالی

## هدف محصول

یک وب‌اپ محلی و فارسی برای ثبت درآمد و هزینه، مدیریت تعهدات و مشاهدهٔ وضعیت ماهانه. داده‌ها روی همان دستگاه و در SQLite نگهداری می‌شوند؛ اکسل فقط منبع اولیهٔ مهاجرت است.

## فاز ۰ — تحلیل و آماده‌سازی داده

- نهایی‌کردن واحد پول و قاعدهٔ نمایش آن
- تعریف دسته‌ها، حساب‌ها و وضعیت‌های پرداخت
- پاک‌سازی و نقشهٔ مهاجرت شیت «تعهدات مالی»
- خروجی: فایل import قابل بازبینی و مدل دادهٔ تأییدشده

## فاز ۱ — هستهٔ قابل استفاده

- مدل‌های `Account`، `Category`، `Transaction`، `Commitment`، `Installment` و `Payment`
- دیتابیس SQLite و API محلی
- فرم ثبت درآمد/هزینه، تعهد و پرداخت کامل یا جزئی
- ورود اولیهٔ اطلاعات اکسل، بدون حذف فایل اصلی
- خروجی: ثبت دادهٔ واقعی و محاسبهٔ ماندهٔ هر سررسید

## فاز ۲ — بودجه و کنترل ماهانه

- بودجهٔ ماهانه برای دسته‌ها
- ساخت خودکار ماه پرداخت از تاریخ واقعی پرداخت
- ماندهٔ بودجه، ماندهٔ تعهدات، سررسید نزدیک و معوق
- فیلتر بر اساس ماه، حساب، دسته و وضعیت
- خروجی: پاسخ دقیق به «این ماه چقدر مانده و چقدر پرداخت شده؟»

## فاز ۳ — داشبورد و گزارش

- داشبورد ماهانه و روند چندماهه
- گزارش پرداخت واقعی در برابر هزینهٔ برنامه‌ریزی‌شده
- گزارش دسته‌ای، حسابی و تعهدی
- خروجی CSV/Excel برای پشتیبان یا تحلیل بیرونی
- خروجی: تصمیم‌گیری سریع با چند شاخص قابل فهم

## فاز ۴ — پایداری و حریم خصوصی

- نسخهٔ پشتیبان و بازیابی دیتابیس
- قفل محلی اختیاری و نگهداری امن فایل‌ها
- تست محاسبات، تست مهاجرت و راهنمای استفاده
- بسته‌بندی اجرای ساده روی سیستم کاربر
- خروجی: برنامهٔ قابل اتکا برای استفادهٔ روزمره

## الزامات سراسری کیفیت

- رابط RTL، فونت محلی Vazirmatn، دسترس‌پذیری کیبورد و پیام‌های `aria-live`.
- راهنمای نزدیک هر بخش و هم‌راستا با منطق واقعی آن.
- ثبت نگارش و رویدادهای حساس، بدون ثبت اطلاعات محرمانه در Git یا رابط کاربری.
- تست واحد، API و رابط برای هر قابلیت تازه؛ ادعای موفقیت فقط بر اساس تست اجراشده.
- احراز هویت، نقش‌ها، پشتیبان‌گیری و بازیابی، پیش از انتشار خارج از localhost الزامی هستند.

## قواعد اصلی داده

1. مبلغ‌ها عدد هستند؛ واحد پول فقط در تنظیمات و نمایش تعریف می‌شود.
2. هر تراکنش واقعی یک رکورد مستقل دارد.
3. هر تعهد می‌تواند چند سررسید داشته باشد.
4. هر سررسید می‌تواند صفر، یک یا چند پرداخت داشته باشد.
5. «روز تا سررسید» و «ماندهٔ مبلغ» دو شاخص جدا هستند.
6. گزارش پرداخت‌شده فقط از تاریخ و مبلغ واقعی پرداخت ساخته می‌شود.
