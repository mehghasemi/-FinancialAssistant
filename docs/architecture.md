# معماری

## مرزبندی اجزا

- `static/`: رابط کاربری فارسی، بدون وابستگی CDN.
- `app/main.py`: قرارداد HTTP و قوانین استفادهٔ API.
- `app/database.py`: اتصال SQLite، schema و ثبت رویدادهای حساس.
- `scripts/import_workbook.py`: ورود کنترل‌شدهٔ اکسل، بایگانی ردیف‌های منبع و تبدیل داده‌های قابل‌تشخیص.
- `app/config.py`: تنظیمات غیرحساس و شمارهٔ نگارش.
- `data/`: دیتابیس محلی کاربر؛ در Git نگهداری نمی‌شود.

## اصول داده

هر `Commitment` چند `Installment` دارد و هر سررسید می‌تواند چند `Payment` داشته باشد. به همین علت مبلغ برنامه‌ریزی‌شده، مبلغ پرداخت واقعی و مانده قابل بازبینی هستند. کاربر تاریخ را شمسی وارد و مشاهده می‌کند؛ برنامه برای مرتب‌سازی و محاسبه، همان تاریخ را فقط در دیتابیس به ISO-8601 تبدیل می‌کند.

هر `import_run` یک هش یکتا از فایل ورودی دارد و به `imported_rows` متصل است؛ بنابراین منبع هر ردیف بایگانی‌شده، قابل‌ردیابی است و اجرای دوبارهٔ واردسازی همان فایل رکورد جدید مالی ایجاد نمی‌کند.

## امنیت فعلی

برنامه با `127.0.0.1` اجرا می‌شود، ورودی‌های API اعتبارسنجی می‌شوند، queryها پارامتری هستند و متن ورودی پیش از نمایش HTML-escape می‌شود. احراز هویت چندکاربره، نقش‌ها و قفل محلی هنوز پیاده‌سازی نشده‌اند و در فاز پایداری قرار دارند.
